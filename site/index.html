.NET web framework

A lightweight, modern web framework for structured UI, REST integration and clean architecture.

WebExpress is a comprehensive all-in-one framework for .NET 10 and Kestrel that embodies an Edge to Cloud strategy. Through its modular plugin system, it integrates web applications, reusable UI controls, and REST APIs into a unified host. By providing all fundamental functions in a single package, WebExpress eliminates complexity and ensures a scalable solution that adapts effortlessly to diverse infrastructure demands.

Introduction

Getting Started with WebExpress

WebExpress provides a .NET 10 host for modular web applications. WebCore manages plugins, applications, routing and HTTP endpoints on Kestrel. WebUI supplies reusable controls, WebApp adds application templates and REST integration, and WebIndex provides full-text indexing and search.

Installation

For development, install the .NET 10 SDK and build the host or a tutorial application. For deployment, download a WebExpress release for your target platform and follow its runtime requirements. The installation guide covers Raspberry Pi setup, systemd integration and production HTTPS.

First Steps

To create an application, start with the HelloWorld tutorial and its separate plugin and host projects. Configure the host in settings/webexpress.settings.json, place packaged plugins in the configured PackagePath and start WebExpress from its installation directory.

Core Concepts

The framework separates hosting from application features. Plugins define applications and endpoints, while UI controls and fragments compose their user interfaces. Choose the libraries that your application requires.

  • WebExpress.WebCore: runtime
  • WebExpress.WebUI: controls
  • WebExpress.WebApp: application templates
  • WebExpress.WebIndex: search index

Minimal configuration (settings/webexpress.settings.json)

{
  "WebExpress": {
    "Endpoints": [
      { "Uri": "http://localhost:8080/" }
    ],
    "ExternalUri": "http://localhost:8080/",
    "Culture": "en-US",
    "PackagePath": "./packages",
    "AssetPath": "./assets",
    "DataPath": "./data"
  }
}

For local development, save this file in the settings directory under the host's working directory and start WebExpress from that working directory. The example listens at http://localhost:8080/. Endpoints defines the listener, while ExternalUri sets the base address used for generated URLs. The package, asset and data paths are relative to the working directory.

For configuration overrides, WebExpress merges the other JSON files in the settings directory in alphabetical order, then the main settings file, followed by environment variables prefixed with WEBEXPRESS_. Plugin settings belong under Plugins in a section named after the plugin ID. Restart the host after changing its settings.

For production HTTPS, configure an HTTPS endpoint and its certificate reference. The configuration guide explains certificate settings, environment overrides and additional server options.

For the full API documentation see the WebCore API docs and the WebUI API docs.

Community

Contribute to WebExpress

WebExpress is open source under the MIT license. Contributions include bug reports, feature ideas, documentation and translations. Please open an issue before starting larger changes to agree on the scope.

Ways to contribute

  • Report bugs through the GitHub issue tracker.
  • Suggest features and discuss them in an issue first.
  • Submit pull requests with tests and documentation.
  • Improve documentation, tutorials and examples.
  • Translate the framework into more languages.
  • Contribution guide
  • Issue tracker
  • Discussions

Guidelines

  • Coding style: follow the conventions used across the framework family.
  • Architecture: keep responsibilities cleanly scoped to Core, UI, App or Index.
  • Tests: bug fixes ship with a regression test; features ship with coverage.
  • Documentation: update READMEs, guides or tutorials together with the change.
